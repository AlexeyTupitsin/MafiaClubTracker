## 1. Базовые понятия

### Команды

| Роль       | Русское название | Команда | Кол-во в игре |
|------------|-----------------|---------|----------------|
| `citizen`  | Мирный          | Красные | 6              |
| `sheriff`  | Шериф           | Красные | 1              |
| `mafia`    | Мафия           | Чёрные  | 2              |
| `don`      | Дон             | Чёрные  | 1              |

Всего в каждой игре участвуют **10 игроков**: 7 красных (6 мирных + шериф) и 3 чёрных (2 мафии + дон).

### Результат игры

Каждая игра заканчивается победой одной из команд:
- **Красные победили** (`winner = "red"`) — мирные вычислили всю мафию
- **Чёрные победили** (`winner = "black"`) — мафия уравняла число игроков

Для каждого игрока результат определяется по его команде:
- Если команда игрока совпала с победителем → **Победа** (`result = "win"`)
- Иначе → **Поражение** (`result = "lose"`)

## 2. Очки за игру (Score)

Система начисления очков за одну игру состоит из трёх компонентов:

### Базовые очки (Base Score)

```
baseScore = (команда игрока === победитель) ? 1 : 0
```

- Победа = **1 очко**
- Поражение = **0 очков**

### Бонусные очки (Bonus Score)

Бонус назначается **вручную** ведущим (админом) для каждого игрока в каждой игре.

| Параметр    | Значение                          |
|-------------|-----------------------------------|
| Диапазон    | от **−5.0** до **+5.0**          |
| Точность    | дробные (0.1, 0.5, 1.5 и т.д.)   |
| По умолчанию | **0** (нет бонуса/штрафа)        |
| Комментарий | необязательный текст-пояснение    |

Бонус — это субъективная оценка ведущего. Может быть положительным (награда за хорошую игру) или отрицательным (штраф за нарушения, плохую игру).

> **Автоматических бонусов/штрафов в системе нет.** Все бонусы — исключительно на усмотрение ведущего.

### Итоговые очки (Total Score)

```
totalScore = baseScore + bonusScore
```

**Примеры:**

| Ситуация | Base | Bonus | Total |
|----------|------|-------|-------|
| Победа, хорошая игра | 1 | +0.5 | 1.5 |
| Победа, без бонуса | 1 | 0 | 1.0 |
| Поражение, отличная игра | 0 | +1.0 | 1.0 |
| Поражение, нарушение | 0 | −0.5 | −0.5 |
| Победа, грубое нарушение | 1 | −2.0 | −1.0 |

## 3. Статистика игрока

Основные показатели, рассчитываемые для каждого игрока по набору игр.

### Формулы

| Показатель | Формула | Описание |
|------------|---------|----------|
| **Всего игр** (`totalGames`) | Количество игр, в которых участвовал игрок | — |
| **Побед** (`wins`) | Количество игр с `result = "win"` | — |
| **Поражений** (`losses`) | `totalGames − wins` | — |
| **Процент побед** (`winrate`) | `(wins / totalGames) × 100` | В процентах, 0 если нет игр |
| **Суммарные очки** (`totalScore`) | `Σ totalScore` по всем играм | Сумма итоговых очков |
| **Средние очки** (`avgScore`) | `totalScore / totalGames` | Средний итоговый балл за игру |
| **Суммарный бонус** (`totalBonus`) | `Σ bonusScore` по всем играм | Сумма всех бонусов |
| **Средний бонус** (`avgBonus`) | `totalBonus / totalGames` | Средний бонус за игру |

### Примечания

- Все показатели рассчитываются **на стороне клиента** (в браузере), а не на сервере.
- Показатели поддерживают **фильтрацию по сезону** — можно увидеть статистику за конкретный сезон или за всё время.
- Фильтрация по турниру — доступна на странице рейтинга (Leaderboard).

## 4. Рейтинговые таблицы

В приложении есть три места, где отображается рейтинг игроков. Они отличаются сортировкой и порогами.

### 4.1. Дашборд (главная страница)

| Параметр | Значение |
|----------|----------|
| **Сортировка по умолчанию** | `totalScore` (суммарные очки), по убыванию |
| **Область данных** | Только текущий сезон |
| **Порог** | 50% от максимального числа игр среди всех игроков |

**Формула порога:**
```
maxGames  = MAX(totalGames) среди всех игроков
threshold = ⌊maxGames / 2⌋
```

Игроки с `totalGames < threshold` скрыты по умолчанию (можно раскрыть).

**Столбцы:** №, Ник, Игры, Победы, WR%, Сумма, Ср. очки, Ср. бонус*, PU%*

\* — скрыты на мобильных устройствах.

### 4.2. Рейтинг (Leaderboard)

| Параметр | Значение |
|----------|----------|
| **Сортировка по умолчанию** | `avgScore` (средние очки), по убыванию |
| **Область данных** | Фильтруется по сезону и/или турниру |
| **Порог** | 50% от общего числа игр в выбранном периоде |

**Формула порога:**
```
totalGamesInPeriod = общее количество игр в выбранном фильтре
minGames = ⌊totalGamesInPeriod × 0.5⌋
```

Игроки с `totalGames < minGames` скрыты по умолчанию.

**Сортируемые столбцы:** Ник, Игры, Победы, WR%, Сумма, Ср. очки, Ср. бонус.
**Несортируемые:** PU%.

### 4.3. Турнирный рейтинг

| Параметр | Значение |
|----------|----------|
| **Сортировка** | `avgScore`, по убыванию (фиксированная) |
| **Область данных** | Только игры конкретного турнира |
| **Порог** | 50% от числа игр турнира, но не менее 1 |

**Формула порога:**
```
minGames = MAX(1, ⌊totalGames × 0.5⌋)
```

**Столбцы:** №, Ник, Игры, Победы, WR%, Сумма, Ср. очки, Ср. бонус.

### Сравнение рейтинговых таблиц

| Критерий | Дашборд | Рейтинг | Турнир |
|----------|---------|---------|--------|
| Сортировка по умолчанию | Суммарные очки | Средние очки | Средние очки |
| Пользовательская сортировка | Да | Да | Нет |
| Порог | 50% от max игрока | 50% от всех игр | 50% от игр турнира |
| PU% | Да | Да | Нет |
| Фильтры | Нет | Сезон + Турнир | Нет |

## 5. Ролевая статистика

Для каждого игрока рассчитываются показатели **отдельно по каждой роли** (мирный, шериф, мафия, дон).

### Формулы (для каждой роли)

| Показатель | Формула |
|------------|---------|
| **Игр за роль** | Количество игр, где игрок выступал в данной роли |
| **Побед за роль** | Количество побед в играх за данную роль |
| **WR% за роль** | `(wins / games) × 100` |
| **Ср. очки за роль** | `Σ totalScore / games` |
| **Ср. бонус за роль** | `Σ bonusScore / games` |
| **PU% за роль** | См. [раздел 7](#7-показатель-первый-убитый-pu) |

### Отображение

- **Профиль игрока:** Таблица + столбчатая диаграмма WR% по ролям
- **Сравнение игроков:** Столбчатая диаграмма WR% по ролям для обоих

## 6. Номинации «Лучший по роли»

Система выбирает лучших игроков для каждой роли.

### Порог участия

```
minGames = MAX(1, ⌊totalGames × 0.1⌋)
```

Игрок должен сыграть за данную роль не менее **10% от общего числа игр**, чтобы попасть в номинацию.

### Критерий ранжирования

Игроки ранжируются по **среднему баллу за роль** (`avgScore`) по убыванию.

### Два формата

#### Дашборд (короткий формат)
- Топ **3** игрока на каждую роль
- Показывает: ник, средний балл, количество игр

#### Рейтинг (расширенный формат)
- Топ **5** игроков на каждую роль
- Показывает: ник, игры, победы, WR%, средний балл, средний бонус

## 7. Показатель «Первый убитый» (PU%)

Отслеживает, как часто игрок выбывает первым в игре (первая жертва ночи).

### Условия

- Учитываются **только сезоны**, где включена настройка `trackFirstKill = true`
- Если сезон не отслеживает первого убитого, данные не собираются

### Формула

```
eligibleGames = игры из сезонов с trackFirstKill, в которых участвовал игрок
timesKilled   = игры, где game.firstKilled === playerId
killRate      = (timesKilled / eligibleGames) × 100
```

### По ролям

PU% также рассчитывается отдельно для каждой роли:

```
eligibleGames = игры из сезонов с trackFirstKill, где игрок выступал за конкретную роль
timesKilled   = из них те, где game.firstKilled === playerId
killRate      = (timesKilled / eligibleGames) × 100
```

### Интерпретация

| PU% | Значение |
|-----|----------|
| **< 10%** | Редко убивают первым (хорошо) |
| **10–25%** | Обычный уровень |
| **> 25%** | Часто убивают первым (плохо) |

## 8. Лучший ход

Фиксирует, насколько точно первый убитый игрок предсказал состав чёрных.

### Условия

- Учитываются **только сезоны**, где включена настройка `trackBestMove = true`
- Лучший ход записывается только для игрока, отмеченного как **первый убитый** в игре
- Поле опционально — если ход не записан, игра не учитывается в статистике

### Механика

В ходе игры первый убитый игрок называет **3 номера мест** (от 1 до 10), которые, по его мнению, занимают игроки чёрной команды (мафия + дон). По итогам игры система определяет, сколько из названных мест действительно оказались чёрными.

### Формула

```
namedSeats  = [место1, место2, место3] (только непустые)
blackSeats  = места игроков с ролью "mafia" или "don"
hits        = |namedSeats ∩ blackSeats|
```

Результат `hits` — целое число от 0 до 3.

> **Примечание:** если записано менее 3 мест, максимально возможное попадание снижается соответственно (2 записанных места — максимум 2 попадания).

### Статистика в профиле игрока

Отображается отдельным блоком в профиле со счётчиками по каждому уровню точности:

| Результат | Описание |
|-----------|----------|
| **3/3** | Все три названных места оказались чёрными |
| **2/3** | Два из трёх |
| **1/3** | Одно из трёх |
| **0/3** | Ни одного попадания |

Для каждой строки показывается: количество раз и процент от общего числа записанных ходов.

```
total = количество игр, где playerId = firstKilled и есть хотя бы одно записанное место
%     = (count / total) × 100, округлённый до целых
```

### Где отображается

- **Профиль игрока** — отдельный блок «Лучший ход» (только если `total > 0`)

## 9. Тренд формы

Анализирует динамику игрока: становится ли он лучше или хуже по сравнению со своей общей статистикой.

### Формула

```
recentGames  = последние 10 игр (отсортированы по дате)
overallWR    = winrate за ВСЕ игры
recentWR     = winrate за последние 10 игр

diff = recentWR − overallWR
```

### Определение тренда

| Условие | Тренд | Отображение |
|---------|-------|-------------|
| `diff > +10` | `"up"` | «На подъёме» (зелёный) |
| `−10 ≤ diff ≤ +10` | `"stable"` | «Стабильно» (жёлтый) |
| `diff < −10` | `"down"` | «В спаде» (красный) |

### Условия отображения

- Тренд **не показывается**, если у игрока менее 3 игр
- Если 0 игр — данные отсутствуют (`null`)

### Дополнительная информация

- `recentWinrate` — WR% за последние 10 игр
- `recentAvgScore` — средний балл за последние 10 игр
- `overallWinrate` — WR% за все игры
- `overallAvgScore` — средний балл за все игры
- `recentResults` — массив результатов (`"win"` / `"lose"`) последних 10 игр (для визуализации серий)

## 10. Парная статистика

Анализирует игры двух конкретных игроков, когда они оба участвовали в одной и той же игре.

### Категории

Для двух игроков **A** и **B** все совместные игры делятся на 4 категории:

| Категория | Описание | Что считается победой |
|-----------|----------|----------------------|
| **Оба красные** | A и B в одной красной команде | Победа красных |
| **Оба чёрные** | A и B в одной чёрной команде | Победа чёрных |
| **A красный, B чёрный** | Играли друг против друга | Считается для A: победа красных |
| **A чёрный, B красный** | Играли друг против друга | Считается для A: победа чёрных |

### Формулы (для каждой категории)

```
games   = количество совместных игр в этой категории
wins    = количество побед (см. столбец «Что считается победой»)
winrate = (wins / games) × 100
```

### Где отображается

- **Профиль игрока:** Таблица парной статистики со всеми игроками, с которыми играл
- **Сравнение игроков:** Блок head-to-head

## 11. Сравнение игроков

Сравнение двух игроков по всем показателям бок о бок.

### Сравниваемые метрики

| Метрика | Подсвечивается лучший? |
|---------|----------------------|
| Всего игр | Нет |
| Побед | **Да** |
| Winrate | **Да** |
| Суммарные очки | **Да** |
| Средние очки | **Да** |
| Средний бонус | **Да** |
| PU% | Нет |

### Счётчик побед

Считается, сколько из 5 подсвечиваемых метрик лучше у каждого игрока:

```
Метрики для сравнения: winrate, wins, totalScore, avgScore, avgBonus
winsA = количество метрик, где A лучше
winsB = количество метрик, где B лучше
```

Результат отображается как «X : Y» (например, «3 : 2»).

### Дополнительно сравниваются

- WR% по каждой роли (столбчатая диаграмма)
- Парная статистика (head-to-head)
- Тренд формы обоих игроков

## 12. Общая статистика сезона

Агрегированные показатели по всем играм в сезоне/периоде.

### Формулы

| Показатель | Формула |
|------------|---------|
| **Всего игр** | Количество игр |
| **Побед красных** | Количество игр с `winner = "red"` |
| **Побед чёрных** | `totalGames − redWins` |
| **WR% красных** | `(redWins / totalGames) × 100` |
| **WR% чёрных** | `(blackWins / totalGames) × 100` |

Отображается на дашборде в виде карточек статистики.

## 14. Цветовая индикация

### Winrate (WR%)

| Условие | Цвет |
|---------|------|
| > 60% | Зелёный + жирный |
| 40–60% | Обычный |
| < 40% | Красный |

### Бонус / Средний бонус

| Условие | Цвет |
|---------|------|

| < 0 | Красный |

### PU% (первый убитый)

| Условие | Цвет |
|---------|------|
| < 10% | Зелёный (хорошо) |
| 10–25% | Обычный |
| > 25% | Красный (плохо) |

### Тренд формы

| Тренд | Цвет | Текст |
|-------|------|-------|
| up | Зелёный | «На подъёме» |
| stable | Жёлтый | «Стабильно» |
| down | Красный | «В спаде» |

### Лучший ход (строки таблицы)

| Результат | Цвет |
|-----------|------|
| 3/3 | Зелёный |
| 2/3 | Жёлто-зелёный |
| 1/3 | Жёлтый |
| 0/3 | Нейтральный (серый) |

## Архитектурная заметка

- **Все метрики вычисляются на клиенте** в файле `src/lib/metrics.js`
- Результаты мемоизируются через `useMemo` для оптимизации
- В БД существуют SQL views (`player_stats`, `player_role_stats`, `season_stats`), но фронтенд их **не использует** — данные загружаются как сырые игры и обрабатываются в браузере
- **Нет системы ELO, Glicko или весовых коэффициентов** — рейтинг основан исключительно на среднем балле
- **Нет затухания по времени** — старые игры имеют тот же вес, что и новые
